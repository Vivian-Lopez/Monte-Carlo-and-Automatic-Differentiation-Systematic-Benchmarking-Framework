\begin{abstract}

Monte Carlo (MC) simulation with automatic differentiation (AD) is important in quantitative finance because both prices and sensitivities must be computed efficiently.  Its performance is difficult to reason about in isolation: workload structure, AD mode, implementation language, compiler/runtime behaviour, and cloud hardware can all change the best engineering choice.  This project addresses that problem by building a reproducible benchmarking framework for MC+AD option-pricing workloads and using it to evaluate engine/runtime performance, AD overhead, cloud cost-performance, and budget-aware profiling.

The framework provides typed workload configurations, a common engine interface, controlled warm-up and repeated timing, deterministic seeding, correctness validation, SQLite result storage, CSV export, and environment metadata capture.  It supports European, Asian, and parametric local-volatility option workloads, with NumPy, JAX/XLA, C++/OpenMP, and Rust/Rayon engines where available.  JAX provides forward- and reverse-mode AD measurements.

The strongest contribution is a Successive Halving style cloud profiler for selecting promising full-scale benchmark configurations from cheap probes.  In the final cloud experiment \texttt{sha\_cloud\_profiler\_v4} on an \texttt{n2-standard-4} VM in \texttt{europe-west1-b}, the full grid contained 16 configurations and 48 full benchmark runs.  The previous profiler selected 30 full runs, whereas SHA selected 24, saving 50.0\% of the full-grid runs while recovering 100.0\% of the full-grid Pareto frontier and incurring 0.0\% runtime and cost regret relative to the grid best.  The best runtime configuration was \texttt{rust/european/none}, taking 0.54 ms at \(M=100{,}000\), and was selected by the full grid, old profiler, and SHA.

The results suggest that no single engine is best for every workload.  Rust/Rayon is strongest for no-AD European and local-volatility CPU runs in the reported experiments, while JAX remains essential for AD.  At \(M=100{,}000\), JAX AD overhead ranged from 1.81\(\times\) for Asian reverse mode to 4.42\(\times\) for local-volatility forward mode.  The project therefore contributes both an engineering artefact and an empirical methodology for cost-aware MC+AD benchmarking, while leaving GPU execution, Mojo, wider BLAS comparisons, hardware counters, wider cloud regions, and distributed execution as future work.

\end{abstract}
