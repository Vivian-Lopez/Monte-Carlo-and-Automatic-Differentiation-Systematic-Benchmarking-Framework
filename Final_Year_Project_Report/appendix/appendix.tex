\section{Reproducibility Package}

The numerical results in this report are generated from stored benchmark
artefacts rather than manually transcribed spreadsheet values. The submitted
project repository contains the reproducibility package under the top-level
\code{results/} directory and the report-specific generated assets under
\code{Final\_Year\_Project\_Report/evaluation/}. The main artefacts are:

\begin{itemize}
    \item \code{results/benchmarks.db}: SQLite database containing benchmark
    runs, workload configurations, timing statistics, environment metadata,
    cloud metadata, profiler decisions, and result values.
    \item \code{results/profiler\_vs\_grid.csv}: exported cloud profiler and
    full-grid comparison rows used for profiler evaluation.
    \item \code{results/cloud\_cost\_analysis.csv}: exported cost-performance
    rows used for the cloud cost tables and plots.
    \item \code{results/pareto\_frontier.csv}: exported Pareto-frontier rows
    used to validate profiler recovery.
    \item \code{results/sha\_progression.csv}: exported SHA promotion and
    elimination trajectory.
    \item \code{results/profiler\_cross\_instance.csv}: post-hoc cross-instance
    profiler robustness audit generated for the final report revision.
\end{itemize}

The report-specific tables and figures are generated into:

\begin{itemize}
    \item \code{Final\_Year\_Project\_Report/evaluation/tables/};
    \item \code{Final\_Year\_Project\_Report/evaluation/figures/}.
\end{itemize}

These files are submitted with the repository. If the report PDF is viewed
without the repository, the most important generated tables are included
directly in Chapter~\ref{chap:results}; the repository artefacts provide the
audit trail for regenerating them.

\section{Regeneration Commands}

The main report artefact generator is
\code{Final\_Year\_Project\_Report/evaluation/generate\_report\_assets.py}. It
reads the stored benchmark exports and regenerates the core tables and figures:

\begin{verbatim}
python3 Final_Year_Project_Report/evaluation/generate_report_assets.py
\end{verbatim}

The cross-instance profiler robustness audit is generated by:

\begin{verbatim}
python3 experiments/analyze_profiler_robustness.py
\end{verbatim}

The report PDF was rebuilt with:

\begin{verbatim}
cd Final_Year_Project_Report
TEXMFVAR=/private/tmp/texmf-var latexmk -pdf \
  -interaction=nonstopmode -halt-on-error main.tex
\end{verbatim}

\section{Traceability Notes}

The SQLite database stores a workload-level \code{config\_hash} together with
engine, AD mode, thread metadata, platform metadata, cloud metadata, and git
commit hash where available. This means the hash alone is not the full
reproducibility key; a specific timed run is identified by the workload hash
plus the execution context stored in the same row.

The cloud-profiler conclusions in Chapter~\ref{chap:results} use both the
\code{sha\_cloud\_profiler\_v4} result set and the guarded local-volatility
artefacts under
\code{results/guarded\_sha\_local\_vol\_gcp/20260611\_152107/combined\_clean/20260611\_153812/}.
The key guarded-SHA files are \code{candidate\_observations.csv},
\code{recommendations.csv}, \code{oracle\_comparison.csv},
\code{sha\_rounds.csv}, \code{summary.json}, and
\code{guarded\_sha\_report.md}.
